# 月落归楼 · 一筒悲欢（AI 抽签说明）

公开签池：`https://raw.githubusercontent.com/millerspeller3311-arch/LILIJO-phone/main/story-lots/pool.json`

公开网页：`https://millerspeller3311-arch.github.io/LILIJO-phone/story-lots/`（需 GitHub Pages 使用 main 分支 /root 发布）

## 给 AI / 角色扮演助手

当用户说“抽一签”“让剧情随机发展”时，读取 pool.json 并执行：

1. 查看 **当前对话中**最近抽签记录，默认喜签概率 0.60，坏签 0.40。
2. 若同一类型已连出至少 3 次：三连喜时下一签喜 0.40；三连坏时下一签喜 0.80。并非强制换签。
3. 抽到喜签：从 `joy` 均匀随机抽一条。
4. 抽到坏签：从 `trouble` 抽两条不同签，再从 `fusions` 均匀随机抽一种叠法。把模板 `{a}`/`{b}` 用坏签标题替换。
5. 尽量不复用最近 5 次出现的签号（坏签不计顺序）；如果全部候选都冲突，才允许重复。
6. 抽签只决定**事件引线**，结合当前角色与世界事实演绎，不要凭空捏造已发生的承诺或记忆，不要替玩家写反应，也不要强迫悬疑查案。
7. 把抽取类型、签号、叠法记录在当前对话中，让下一次抽签可维持去重与连续概率。

**重要限制：** GitHub Pages 只能托管静态文件，不能提供会永久更新的随机抽签 API。浏览器每次点击是本地随机抽签，结果只在该浏览器保存；AI 读签池后进行自己的随机抽取，不会共享浏览器摇签历史。如果需要所有设备与 AI 共享同一抽签序列，后续需加有状态服务器 / 数据库。

## 数据结构

- `rules`：概率、柔性纠偏、避重参数
- `joy`：26 条喜签，含 id/title/description
- `trouble`：12 条坏签，双签从中抽不重复两条
- `fusions`：8 种叠法，含 id/title/template
